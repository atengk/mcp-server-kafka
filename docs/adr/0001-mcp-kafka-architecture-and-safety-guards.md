# 0001: Kafka MCP 整体架构形态与双重安全防线设计

针对大语言模型与 AI 智能体接入企业级 Apache Kafka 集群的场景，我们决定采用全功能覆盖形态（涵盖集群元数据、主题操作、消息生产、只读采样读取以及消费组积压诊断），并全面提供 MCP Tools、Resources 与 Prompts 三位一体能力。同时，为防范智能体意外破坏生产集群，架构引入全局只读开关 (`--read-only`) 与破坏性写操作显式确认机制 (`confirm=True`)。

## 决策背景

Kafka 是支撑企业核心交易与数据流转的分布式中枢，AI 智能体直接操作 Kafka 时面临极高的误操作风险（如误删核心主题、误清空数据等）。因此单纯开放全部读写或极端采用纯只读都无法兼顾排查调试与生产安全，必须在架构顶层设计明确的安全边界与分层控制。

## 决策内容

1. **三位一体协议形态**：
   - **Tools**：承载主动操作（如创建主题、发送消息、只读采样拉取消息、查询积压量）；
   - **Resources**：暴露只读动态上下文资源（如 `kafka://cluster`、`kafka://topics/{topic}`）；
   - **Prompts**：预设常见运维分析模板（如消费积压根因诊断、主题消息样本分析）。
2. **双重安全防线**：
   - 一级防线：支持全局只读模式开关（配置参数 `--read-only` 或环境变量 `MCP_KAFKA_READ_ONLY=true`），开启时阻断一切写操作并仅向模型暴露只读工具；
   - 二级防线：在常规读写模式下，对 `delete_topic` 等高危破坏性工具施加显式二次确认校验（参数强制要求 `confirm=True`）。
3. **认证与网络兼容性**：
   - 支持 `PLAINTEXT` 及 `SASL_PLAINTEXT` / `SASL_SSL`（PLAIN、SCRAM-SHA-256、SCRAM-SHA-512），保证既能兼容本地轻量调试，也能接入生产云托管集群。
