# 0004: 多集群命名连接配置与无状态路由架构设计

针对多环境（开发/测试/预发/生产）与多 Kafka 集群并存的治理场景，我们决定引入基于 YAML 配置文件的多集群命名连接机制 (`--config connections.yaml`)，并在所有 MCP 工具中提供可选的 `connection` 参数，实现单进程内对多套 Kafka 集群的无状态动态路由与细粒度只读保护。

## 决策背景

在企业实际开发与运维场景中，开发者与运维人员往往面对多套物理隔离的 Kafka 集群（例如 `default` 本地单机、`staging` 联调集群、`production` 生产核心集群）。若仅支持单连接绑定，客户端需启动多个进程或在频繁切换中面临配置污染。同时，需要确保生产环境与测试环境能够实施差异化的安全策略（例如生产集群强制只读，测试集群允许发送测试消息）。

## 决策内容

1. **双轨向后兼容配置模型**：
   - **单连接模式（默认兼容）**：未提供 `--config` 时，系统继续完全支持 `--bootstrap-servers` 命令行参数与环境变量 `MCP_KAFKA_BOOTSTRAP_SERVERS`，并自动隐式将其作为名为 `default` 的单集群连接；
   - **多连接模式（声明式扩展）**：通过 `--config <path>`（或环境变量 `MCP_KAFKA_CONFIG`）指定 YAML 配置文件，支持定义全局默认连接别名 (`default_connection`) 与包含多套集群连接的 `connections` 字典。

2. **无状态动态路由 (Stateless Routing)**：
   - 在所有 MCP 工具（Tools）中增加可选入参 `connection: str | None = None`；
   - 工具执行时根据传入的连接别名动态从连接注册表 (`KafkaManagerRegistry`) 调度对应的 `KafkaManager` 实例；若未显式传参则自动平滑回退至 `default_connection`；
   - 保持公共单例服务与工具调用的完全无状态（Stateless），规避上下文状态竞争与并发安全隐患。

3. **双层只读安全防线联动**：
   - **全局层**：若配置了全局 `read_only: true`（或 CLI 参数 `--read-only`），则所有连接的全部写操作（创建主题、删除主题、生产消息）均被全局阻断；
   - **连接级细粒度层**：各集群连接配置项可独立配置 `read_only: true`（如生产环境连接）。即便全局未开启只读，针对该生产连接的一切写操作也将被精准拦截并显式报错拒绝。

4. **连接拓扑探查能力**：
   - 增加轻量级工具 `kafka_list_connections`，供大语言模型自主发现当前运行环境中已配置的所有 Kafka 集群别名、引导地址及只读状态，增强智能体的环境感知能力。
