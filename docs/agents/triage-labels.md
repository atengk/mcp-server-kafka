# 缺陷与需求分流标签体系 (Triage Labels)

各项工程技能围绕五大标准分流角色开展工作。本文档定义了这五大规范角色与本项目 GitHub Issues 实际标签字符串的映射关系。

| 技能规范角色名 | 本项目实际标签 (Label) | 业务与流转含义 |
| :--- | :--- | :--- |
| `needs-triage` | `needs-triage` | 待分流：需要维护者或评审者评估其合理性与优先级 |
| `needs-info` | `needs-info` | 待补充信息：等待反馈者提供复现步骤、日志或补充背景 |
| `ready-for-agent` | `ready-for-agent` | 代理就绪：规格与上下文已完全完备，可直接交由自主 Agent 执行 |
| `ready-for-human` | `ready-for-human` | 人工介入：逻辑涉及架构权衡或外部敏感授权，需人工开发实现 |
| `wontfix` | `wontfix` | 不予解决：非设计缺陷、超出维护范围或已废弃不再处理 |

## 智能体协作约定

当任何工程技能在交互中提及角色概念时（例如“为该工单挂载代理就绪标签”、“将其标记为待补充信息”）：
- 必须严格映射为上表中“本项目实际标签”列对应的确切字符串；
- 严禁随意创建或发明表中未定义的同义词标签（如避免随意创建 `todo`、`waiting` 等）。
