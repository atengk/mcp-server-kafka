# 0002: 瞬态无侵入消息采样与 Stdio/SSE 双模传输架构

在实现消息内容探测与客户端接入时，我们决定采用只读瞬态采样模式（零消费组位移提交），配合自适应消息内容解析机制；同时在服务端对外通信上统一提供标准管道 (Stdio) 与常驻 HTTP (SSE) 双模传输网关。

## 决策背景

1. **消费进度隔离**：如果大语言模型使用常规消费模式并提交消费位移，将直接破坏生产环境中正在运行的真实业务消费者数据流；因此排查类读取必须与生产消费进度物理隔离。
2. **通信场景多样性**：桌面客户端（如 Claude Desktop）偏好基于子进程的 Stdio 标准输入输出管道，而容器化生产部署（如 Docker、Kubernetes）则要求常驻 HTTP SSE 网络端口服务。

## 决策内容

1. **零侵入瞬态消息采样 (Ephemeral Fetch)**：
   - 消息采样读取不加入正式业务消费组，强制关闭自动位移提交 (`enable_auto_commit=False`)；
   - 灵活支持从最新 (`latest`)、最旧 (`earliest`) 或指定分区具体 `offset` 开始采样读取前 N 条消息。
2. **智能自适应消息反序列化**：
   - 优先尝试 UTF-8 文本解析，若检测为标准 JSON 格式自动反序列化为结构化对象；
   - 遇到无法解码的二进制字节流自动降级编码为 Base64 字符串，并始终随附消息键 (Key)、分区、位移、时间戳及标头 (Headers) 元数据。
3. **Stdio 与 HTTP SSE 双模通信**：
   - 默认模式：`--transport stdio`，适用于单机本地客户端与 IDE 插件；
   - 网络常驻模式：`--transport sse --host 0.0.0.0 --port 8000`，适用于容器化服务与远程连接。
